# القرار المعماري

## تطبيق الموبايل

Flutter مع Riverpod وبنية Feature-first. كل شاشة تعتمد على عقد `AppRepository` بدل الوصول المباشر إلى Supabase. التنفيذ الحالي يستخدم `MockAppRepository` كي يعمل العرض بلا مفاتيح، ويُستبدل لاحقًا بمستودع Supabase من موضع واحد.

## البيانات

Supabase/PostgreSQL مع PostGIS. الحساب منفصل عن الملف الشخصي والمنشأة، وملكية المنشآت متعددة عبر `business_members`. المواقع الدقيقة مخصصة للفروع، بينما ملف الفرد يحتفظ بموقع تقريبي ومنطقة خدمة.

## البحث

البداية تعتمد PostgreSQL Full Text Search مع فهارس GIN وPostGIS مع GiST. طبقة المستودع تسمح بإضافة Typesense أو Meilisearch عندما يبرر حجم البيانات ذلك.

## الملفات والخدمات الخارجية

الصور لا تدخل PostgreSQL؛ تحفظ الروابط والبيانات الوصفية فقط. Supabase Storage مناسب للتجربة، وCloudflare R2 خيار الإنتاج خلف واجهة تخزين موحدة. فتح الاتجاهات يتم عبر تطبيق الخرائط الخارجي.

## الأمن

المفتاح العام فقط داخل تطبيق الموبايل، ولا يستخدم Service Role في العميل. الصلاحيات الفعلية في RLS، مع وظائف محمية لفحص موظفي الإدارة وأعضاء المنشأة والمحادثة. التوثيق ومستنداته وعمليات الإدارة ليست عامة.

## البيئات

Development وStaging وProduction بقيم منفصلة. لا تُخزن الأسرار في Git، ويحتوي المشروع على `.env.example` لأسماء الإعدادات فقط.
